## Overview

Atlas supports the [Model Context Protocol](https://modelcontextprotocol.io/) (MCP), an open standard from Anthropic for connecting AI assistants to external data and tools. Atlas implements the Streamable HTTP transport and current MCP authorization draft behavior, which means compliant MCP clients — Claude, GitHub Copilot, Google Gemini, Codex, Inspector, and others — can talk to Atlas without custom integration. Instead of clicking through a website or writing API calls, you ask questions in natural language and get structured answers backed by Atlas data.

**Example conversation with Claude:**

> **You:** Who's working on housing issues in Kansas City?
>
> **Claude:** I found 23 entities working on housing in Kansas City. Here are the most prominent...
>
> **You:** What are the coverage gaps?
>
> **Claude:** Kansas City has strong coverage on housing affordability and tenant organizing, but limited coverage on homelessness services and community land trusts...

## What you need

<RequiresPaidPlan />

1. **An Atlas account** — [Sign up](https://atlas.rebuildingus.org) if you haven't already.
2. **Atlas Pro or Team plan** — MCP access requires a paid plan ([see pricing](/account/pricing)). Free-tier sign-ins succeed but the MCP endpoint returns a `403 Forbidden` with `WWW-Authenticate: Bearer error="insufficient_scope"` and an `error_uri` pointing at the pricing page until a plan is active.
3. **An MCP-compatible client** — Claude Desktop, Claude Code, VS Code with Copilot, Gemini CLI, Codex CLI, or Copilot CLI.

<Note>
**Before you connect**

- **Bootstrap allowlist.** Atlas runs an operator allowlist while we're inviting users from the bootstrap list. If your email isn't on it and you don't have a workspace invitation, the OAuth sign-in won't deliver a magic link. Request access at [atlas.rebuildingus.org](https://atlas.rebuildingus.org) before connecting an MCP client.
- **Workspace binding.** After signing in, your primary workspace is bound to OAuth tokens automatically. Multi-workspace users see a workspace picker on the consent screen — MCP clients don't need to compute or pass an `org:{workspace_id}` scope.
- **Token lifecycle.** Access tokens expire after 15 minutes; refresh tokens rotate on every exchange and are revoked on reuse. Most MCP clients handle this transparently.
</Note>

## How it works

Atlas runs a remote MCP server at:

<McpServerUrl />

When you connect your AI assistant to this server, it gains access to Atlas's search, discovery, and place-level civic data tools. Authentication happens automatically — a compliant client opens a browser window for you to sign in and approve access on first use.

## Available tools

Once connected, your AI assistant can use these tools:

| Tool | What it does |
|------|-------------|
| `search_entities` | Search Atlas entities by place, topic, or text |
| `get_entity` | Get details for a specific entity |
| `get_entity_sources` | Get the sources backing an entity |
| `search_sources` | Search across all Atlas sources |
| `get_place_entities` | Get entities for a specific place |
| `list_discovery_runs` | List source-linked research runs |
| `get_discovery_run` | Get one research run and its structured output |
| `get_place_profile` | Demographic and socioeconomic context for a place |
| `get_place_coverage` | Coverage gaps and entity counts for a place |
| `get_place_issue_signals` | Issue area summary for a place |
| `get_related_entities` | Entities related through Atlas relationships |
| `resolve_issue_areas` | Map natural language to Atlas issue area slugs |

<Tip>
See [Available tools](/mcp/tools) for detailed parameter descriptions and example prompts for each tool.
</Tip>

## Workspace monitoring

Workspace admins can see successful REST API and MCP activity in Integration monitoring: total calls, API calls, MCP calls, top resources, and last-seen timestamps. Atlas does not expose request payloads, prompts, raw metadata, private notes, or session replay in that view.

See [Integration monitoring](/mcp/integration-monitoring) for the access requirements and data boundary.

<Tab title="Claude Code" id="claude-code" icon="terminal">
Claude Code supports remote MCP servers via the `claude mcp add` command.

```bash
claude mcp add --transport http atlas https://atlas.rebuildingus.org/mcp
```

To make Atlas available across all projects, add `--scope user`:

```bash
claude mcp add --transport http --scope user atlas https://atlas.rebuildingus.org/mcp
```

Run `/mcp` inside a Claude Code session to trigger the OAuth flow. A browser
window will open for you to sign in and approve access.

To share the Atlas connection with collaborators, add it to your project's
`.mcp.json`:

```json
{
  "mcpServers": {
    "atlas": {
      "type": "http",
      "url": "https://atlas.rebuildingus.org/mcp"
    }
  }
}
```

Commit `.mcp.json` to version control. Each collaborator completes their own
OAuth flow on first use.
</Tab>

<Tab title="Gemini CLI" id="gemini" icon="sparkles">
Gemini CLI supports remote MCP servers with automatic OAuth discovery.

```bash
gemini mcp add atlas "https://atlas.rebuildingus.org/mcp" \
  --transport http \
  --scope user
```

You can also edit `~/.gemini/settings.json` directly:

```json
{
  "mcpServers": {
    "atlas": {
      "url": "https://atlas.rebuildingus.org/mcp",
      "type": "http"
    }
  }
}
```

Gemini CLI discovers Atlas's OAuth server automatically. On first use, it opens a
browser for you to sign in and approve access. You can also trigger the OAuth
flow manually:

```text
/mcp auth atlas
```
</Tab>

<Tab title="Codex CLI" id="codex" icon="robot">
Codex CLI uses TOML configuration and an explicit OAuth login command.

Edit `~/.codex/config.toml` or `.codex/config.toml` in your project root:


Codex starts a local callback server, opens your browser, and stores tokens
securely. Later sessions reuse the stored credentials automatically.

<Tab title="Other MCP clients" id="other-clients" icon="plug">
Any MCP client that supports remote HTTP MCP servers and the current MCP
authorization flow can connect to Atlas.

```text
https://atlas.rebuildingus.org/mcp
```

If your client asks for a transport, choose **HTTP** or **Streamable HTTP**. If
it asks for authentication, choose the automatic OAuth flow. Atlas publishes the
metadata a compliant client needs, so the server URL should be enough.

If your client only supports local `stdio` servers, SSE-only remote servers, or

Atlas.

## Troubleshooting

**"Connection failed" or timeout**
Check that `https://atlas.rebuildingus.org/mcp` is reachable from your network. If you're behind a corporate proxy, ensure it allows outbound HTTPS.

**OAuth window doesn't open**
Make sure your default browser is set correctly and your MCP client supports remote OAuth login.

**"Unauthorized" after connecting**
Your OAuth token may have expired. Disconnect and reconnect the server in your client to trigger a fresh authorization flow.

**Tools don't appear**
Restart your MCP client after connecting. Some clients require a reload to discover newly available tools.

For more help, see [MCP troubleshooting](/mcp/troubleshooting) or the general [Troubleshooting](/resources/troubleshooting) guide.

## References

Atlas builds on the published MCP specification and the OAuth 2.1 family of standards. These references are useful background for understanding what compliant clients are doing automatically:

- [MCP base protocol — current draft](https://modelcontextprotocol.io/specification/draft/basic) — Lifecycle, transports, and session semantics.
- [MCP authorization — current draft](https://modelcontextprotocol.io/specification/draft/basic/authorization) — The authorization behavior used by compliant remote MCP clients.
- [MCP Streamable HTTP transport — current draft](https://modelcontextprotocol.io/specification/draft/basic/transports#streamable-http) — The remote transport Atlas supports.
- [MCP security best practices](https://modelcontextprotocol.io/specification/draft/basic/security_best_practices) — Token audience validation, token passthrough prohibitions, confused-deputy mitigations.
- [MCP Registry](/mcp/registry) — How Atlas lists itself and how clients discover it.
- [Authentication reference](/api-reference/authentication) — Token lifecycle, refresh rotation, and the discovery URL catalog.
