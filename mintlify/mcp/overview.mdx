## Overview

Atlas supports the [Model Context Protocol](https://modelcontextprotocol.io/) (MCP), an open standard from Anthropic for connecting AI assistants to external data and tools. Atlas implements the Streamable HTTP transport and current MCP authorization draft behavior, which means compliant MCP clients — Claude, GitHub Copilot, Google Gemini, Codex, Inspector, and others — can talk to Atlas without custom integration. Instead of clicking through a website or writing API calls, you ask questions in natural language and get structured answers backed by Atlas data.

**Example conversation with Claude:**

> **You:** Who's working on housing issues in Kansas City?
>
> **Claude:** I found 23 entities working on housing in Kansas City. Here are the most prominent...
>
> **You:** What are the coverage gaps?
>
> **Claude:** Kansas City has strong coverage on housing affordability and tenant organizing, but limited coverage on homelessness services and community land trusts...

## What you need

<RequiresPaidPlan />

1. **An Atlas account** — [Sign up](https://atlas.rebuildingus.org) if you haven't already.
2. **Atlas Pro or Team plan** — MCP access requires a paid plan ([see pricing](/account/pricing)). Free-tier sign-ins can complete, but Atlas tools stay unavailable until a plan is active.
3. **An MCP-compatible client** — Claude Desktop, Claude Code, VS Code with Copilot, Gemini CLI, Codex CLI, or Copilot CLI.

<Note>
**Before you connect**

- **Bootstrap allowlist.** Atlas runs an operator allowlist while we're inviting users from the bootstrap list. If your email isn't on it and you don't have a workspace invitation, the OAuth sign-in won't deliver a magic link. Request access at [atlas.rebuildingus.org](https://atlas.rebuildingus.org) before connecting an MCP client.
- **Workspace binding.** After signing in, your primary workspace is selected automatically. Multi-workspace users see a workspace picker on the consent screen.
- **Session lifecycle.** Most MCP clients keep the connection fresh automatically. If Atlas asks you to sign in again, complete the browser flow.

</Note>

## How it works

Atlas runs a remote MCP server at:

<McpServerUrl />

When you connect your AI assistant to this server, it gains access to Atlas's search, discovery, and place-level civic data tools. Authentication happens automatically — a compliant client opens a browser window for you to sign in and approve access on first use.

Atlas also exposes durable MCP resources for selected research artifacts. Tools
find the relevant records, then resources let clients re-read source-linked
briefs, source trails, and place coverage summaries as context. Atlas does not
list the entire entity catalog as MCP resources.

## Available tools

Once connected, your AI assistant can use these tools:

| Tool                      | What it does                                      |
| ------------------------- | ------------------------------------------------- |
| `search_entities`         | Search Atlas entities by place, topic, or text    |
| `get_entity`              | Get details for a specific entity                 |
| `get_entity_sources`      | Get the sources backing an entity                 |
| `search_sources`          | Search across all Atlas sources                   |
| `get_place_entities`      | Get entities for a specific place                 |
| `list_discovery_runs`     | List source-linked research runs                  |
| `get_discovery_run`       | Get one research run and its structured output    |
| `get_place_profile`       | Demographic and socioeconomic context for a place |
| `get_place_coverage`      | Coverage gaps and entity counts for a place       |
| `get_place_issue_signals` | Issue area summary for a place                    |
| `get_related_entities`    | Entities related through Atlas relationships      |
| `resolve_issue_areas`     | Map natural language to Atlas issue area slugs    |
| `start_discovery_run`     | Start a source-linked research run                |

## Available resources

Compatible clients can read Atlas resources for durable research context:

| Resource | What it provides |
| -------- | ---------------- |
| `atlas://discovery-runs/{run_id}` | Structured discovery-run record |
| `atlas://discovery-runs/{run_id}/brief` | Source-linked research brief |
| `atlas://discovery-runs/{run_id}/sources` | Sources referenced by a run summary |
| `atlas://entities/{entity_id}/sources` | Public source trail for one entity |
| `atlas://cities/{place_key}/coverage` | City coverage summary |
| `atlas://states/{state}/coverage` | State coverage summary |

`resources/list` returns a small research shelf. Use tools to search the full
Atlas catalog, then use returned `resource_uri` values when your client needs to
pin or re-read an artifact.

## Guided prompts

Compatible MCP clients can also show Atlas prompts as user-selected commands.
Use them when you want a guided starting point for common civic research jobs:
researching a place, finding civic actors, inspecting an entity's source trail,
assessing coverage gaps, or creating a brief from an existing discovery run.

Prompts are read-only in this version. They guide your assistant toward the
right Atlas tools and source-checking steps, but they do not create discovery
runs or modify workspace data.

<Tip>
  See [Available prompts](/mcp/prompts) for prompt names, arguments, and usage
  examples.
</Tip>

## Long-running research runs

Most tools answer from Atlas data that already exists. `start_discovery_run`
starts new source-linked research, so it returns a task handle for clients that
support MCP task-augmented tool calls. Task-aware clients can poll until the run
finishes instead of leaving the conversation blocked.

Clients without task support receive an explicit error. Use
`list_discovery_runs` or `get_discovery_run` to check on runs started elsewhere.

## Workspace admin activity

Workspace admins can see successful integration activity by surface: total calls, API calls, MCP calls, top paths, and last-seen timestamps. Atlas does not expose request payloads, prompts, raw metadata, private notes, or session replay in that view.

## Connect from a compliant client

Every supported client uses the same Atlas endpoint. Use your MCP client's built-in flow for adding a remote Streamable HTTP server, then provide the Atlas server URL:

```text
https://atlas.rebuildingus.org/mcp
```

Atlas expects a compliant client that supports remote Streamable HTTP MCP servers and browser-based OAuth. The client should open a browser for Atlas sign-in and consent the first time it needs access. Clients that only support local `stdio` servers or SSE-only remote servers cannot use the hosted Atlas MCP server.

After connecting, see [Available tools](/mcp/tools), [Available resources](/mcp/resources), or [Tutorial: Research a city](/mcp/tutorials/research-city) for a complete session.

## Troubleshooting

**"Connection failed" or timeout**
Check that `https://atlas.rebuildingus.org/mcp` is reachable from your network. If you're behind a corporate proxy, ensure it allows outbound HTTPS.

**OAuth window doesn't open**
Make sure your default browser is set correctly and your MCP client supports remote OAuth login.

**"Unauthorized" after connecting**
Your OAuth token may have expired. Disconnect and reconnect the server in your client to trigger a fresh authorization flow.

**Tools don't appear**
Restart your MCP client after connecting. Some clients require a reload to discover newly available tools.

For more help, see [MCP troubleshooting](/mcp/troubleshooting) or the general [Troubleshooting](/resources/troubleshooting) guide.
